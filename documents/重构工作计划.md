# 重构工作计划（Work Plan v1.0）

本文档依据 `documents/重构实施方案 v3.md` (v3.1) 制定，旨在指导项目的阶段性开发与重构实施。

---

## 1. 重构目标与核心机制回顾

- **核心价值**：将视觉形象（图像特征）关联到凭证标记（`passcode` / `credential_value`），在服务端建立一对多的特征索引库，实现去中心化或轻量化的视觉密语验证与检索。
- **前端职责**：相机画面采集 -> 凭证自动识别提取（二维码/条形码/语音等获取 `passcode`，手动输入作为备选） -> 图像标准化预处理（缩放 480p/640p、灰度化、去噪增强） -> `OpenCV.js`（Web Worker）提取 ORB 特征描述子 -> 序列化为 Base64 格式并组装 `VerifyRequest` 提交。
- **后端职责**：接收 `VerifyRequest` -> 按 `passcode` 检索数据库中**所有符合该 passcode 的候选特征库记录（一对多）** -> OpenCV-Python 矩阵高精度比对（BFMatcher/KNN + Lowe's ratio test 计算匹配分值） -> 按有效阈值（如 `min_score = 0.60`）过滤并降序排序 -> **返回匹配度高于阈值的前 5 个结果（Top-5）**及对应解密密语。

---

## 2. 阶段工作规划与任务清单

### 阶段一：前后端数据契约与数据库层改造（Phase 1: Contracts & Database）

**目标**：统一前后端命名体系，废除历史混乱字段，升级数据库模型以支持“同一个 passcode 对应多条记录（一对多）”的特征存储与索引。

- [ ] **任务 1.1：创建统一的 Pydantic 数据契约 (`app/domain/schemas/`)**
  - 定义 `evidence.py`：`VisualEvidence`、`VerifyRequest`、`MatchItem`、`VerifyResponse`、`SecretCreateRequest`。
  - 确保字段命名统一为 `credential_type`, `credential_value`, `algorithm`, `feature_data`, `score` 等。
- [ ] **任务 1.2：数据库模型重构与索引设计 (`app/domain/models/` 或 `app/services/database.py`)**
  - 修改 `SecretEntry` 模型：
    - 移除 `pass_code` 唯一约束（`unique=True` -> `index=True`），支持同一个 `credential_value` / `passcode` 存在多个特征条目（一对多）。
    - 字段统一：`id`, `title`, `credential_type`, `credential_value` (建立索引), `algorithm`, `feature_data` (Base64/二进制描述子), `keypoints_count`, `secret_text`, `extra_features`, `created_at`, `viewed_at`。
- [ ] **任务 1.3：数据库操作服务更新**
  - 新增根据 `credential_value` 查询候选特征列表函数：`find_candidates_by_credential(credential_value: str) -> List[SecretEntry]`。
  - 更新新增记录逻辑 `create_secret_entry(...)`。

---

### 阶段二：后端算法引擎与 Top-5 决策比对重构（Phase 2: Backend Match Engine & API）

**目标**：重构特征反序列化与比对服务，实现多候选库并行比对与 Top-5 结果筛选。

- [ ] **任务 2.1：ORB 描述子反序列化与匹配器 (`app/services/matchers/orb.py`)**
  - 实现从 Base64 还原为 NumPy `(N, 32)` `uint8` 描述子矩阵。
  - 使用 `cv2.BFMatcher(cv2.NORM_HAMMING)` 执行 KNN 匹配 (`k=2`)，应用 Lowe's ratio test (`ratio <= 0.75`) 筛选 Good Matches。
  - 计算归一化匹配度得分 `score` (0.0 ~ 1.0)。
- [ ] **任务 2.2：可扩展匹配器架构与接口设计 (`app/services/matchers/base.py`)**
  - 定义 `BaseMatcher` 抽象基类，预留哈希扩展（`aHash`, `dHash`, `pHash`）接口。
- [ ] **任务 2.3：决策匹配引擎 (`app/services/match_engine.py`)**
  - 实现 `match_evidence_against_candidates(evidence: VisualEvidence, candidates: List[SecretEntry], min_score: float) -> VerifyResponse`。
  - 遍历所有候选特征，比对计算得分；过滤 `score >= min_score` 的条目；按得分降序排序并截取 Top-5。
- [ ] **任务 2.4：API 路由改造 (`app/routers/` / `app/api/`)**
  - 重构/新增 `POST /api/v1/verify`：接收 `VerifyRequest`，调用决策引擎，返回包含 Top-5 结果列表的 `VerifyResponse`。
  - 重构/新增 `POST /api/v1/secrets`：录入新密语及关联特征。
  - 异步性能优化：CPU 密集型 OpenCV 比对调用 `run_in_threadpool`。

---

### 阶段三：前端架构重构与预处理链路实现（Phase 3: Frontend SPA & OpenCV.js）

**目标**：基于 React + Vite + TanStack 搭建轻量应用，完成相机采集、凭证解析与 OpenCV.js Web Worker 提取。

- [ ] **任务 3.1：前端工程搭建**
  - 采用 React + Vite + TypeScript + TailwindCSS / shadcn-ui + TanStack Router / TanStack Query 搭建应用架构。
- [ ] **任务 3.2：凭证自动检测模块 (`RecognitionService`)**
  - 集成 `@zxing/browser`，在相机实时流中自动捕获 QR / Barcode。
  - 提取凭证值作为 `passcode` / `credential_value`。
  - 支持备选方案：手动输入 passcode 或 iOS Safari 语音识别 passcode。
- [ ] **任务 3.3：图像预处理与 OpenCV.js Web Worker (`ImagePreprocessService`)**
  - 相机帧标准化处理：分辨率缩放 (480p/640p)、灰度化 (`BGR2GRAY`)、去噪与对比度增强 (CLAHE)。
  - Web Worker 内部加载运行 `@techstark/opencv-js`，提取 ORB 描述子，序列化为 Base64 编码。
- [ ] **任务 3.4：比对结果与 Top-5 列表展示**
  - 发起 `POST /api/v1/verify` 请求。
  - 界面展示命中状态、匹配度得分（Top-1~5 卡片式列表）以及匹配成功的密语内容。

---

### 阶段四：集成测试、阈值调优与交付（Phase 4: Testing & Tuning）

**目标**：验证在不同光照、角度、缩放及一对多候选集场景下的识别率与延迟。

- [ ] **任务 4.1：测试数据与自动化测试用例构建**
  - 在 `test_data/` 中扩充包含不同旋转、模糊、光照变化的图片测试集。
  - 编写单元测试与 API 集成测试（`pytest`），覆盖：单 passcode 多记录检索、空候选集、ORB 精度打分、Top-5 截断与排序逻辑。
- [ ] **任务 4.2：参数标定与性能调优**
  - 标定最佳参数：ORB 特征点数（如 `nfeatures=500`）、Lowe's ratio（0.75）、判定门限 `min_score`（0.60 ~ 0.70）。
  - 测量端到端延迟（相机捕获 -> 前端 Worker 提取 -> 网络传输 -> 后端多特征库检索与比对）。
- [ ] **任务 4.3：文档与部署更新**
  - 更新 Dockerfile / docker-compose 配置。
  - 整理完整的 API 文档与联调指南。
